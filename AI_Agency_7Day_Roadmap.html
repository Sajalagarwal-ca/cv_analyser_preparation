Day 1 — Backend Foundations + Your First LLM API

Learning objectives

  • Understand a backend = a process listening on a port returning JSON.
  • Build, run, and call your first FastAPI server that wraps an LLM.

Concepts to internalize

  • Request/Response cycle: Client → HTTP request → Server → JSON response.
  • REST endpoints: verbs + paths + body.
  • Env vars: never hardcode API keys; use .env.
  • Stateless servers: each request is independent unless persisted.
  • Why FastAPI: async by default, auto OpenAPI docs at /docs, Pydantic validation via type hints.

Tools / libraries

fastapi, uvicorn, pydantic, python-dotenv, openai, httpx

Hands-on mini project: "Echo-GPT" API

# app.py
from fastapi import FastAPI, HTTPException, Header
from pydantic import BaseModel
from openai import OpenAI
from dotenv import load_dotenv
import os

load_dotenv()
client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))
APP_API_KEY = os.getenv("APP_API_KEY")

app = FastAPI(title="EchoGPT")

class ChatIn(BaseModel):
    message: str
    system: str | None = "You are a helpful assistant."

class ChatOut(BaseModel):
    reply: str

@app.get("/health")
def health():
    return {"status": "ok"}

@app.post("/chat", response_model=ChatOut)
def chat(body: ChatIn, x_api_key: str = Header(...)):
    if x_api_key != APP_API_KEY:
        raise HTTPException(401, "Invalid API key")
    resp = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": body.system},
            {"role": "user", "content": body.message},
        ],
    )
    return ChatOut(reply=resp.choices[0].message.content)

Run: uvicorn app:app --reload → open http://localhost:8000/docs.

Architecture

[curl / Postman / Browser] --HTTPS--> [FastAPI :8000] --HTTPS--> [OpenAI API] | .env (keys)

Common mistakes avoid

  • Committing .env to git. Add to .gitignore on minute one.
  • Skipping response_model — lose validation and docs.
  • Heavy async app calling sync SDK; sync is fine for now.
Advanced tip optional: use AsyncOpenAI + async def endpoints from the start if you expect concurrency.

Day 2 — RAG Pipeline: Answer from YOUR Documents

Learning objectives

  • End-to-end RAG: ingest → chunk → embed → store → retrieve → generate.
  • Understand why each step exists.

Concepts

  • Chunking: 300–800 tokens, ~50–100 overlap.
  • Embeddings: text → fixed-length vector; similar meaning → similar vector.
  • Vector DB: fast nearest-neighbor search. Qdrant / Pinecone / Weaviate / pgvector.
  • RAG: stuff top-K chunks into the prompt. The LLM reads, it doesn't learn.
  • RAG vs fine-tune: RAG is cheap, updatable, traceable. Fine-tune is for style/format, not knowledge.

Tools / libraries

langchain, langchain-openai, langchain-community, qdrant-client, pypdf, tiktoken

Run Qdrant: docker run -p 6333:6333 qdrant/qdrant

Mini project: "Docs Bot"

# ingest.py
from langchain_community.document_loaders import DirectoryLoader, PyPDFLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings
from langchain_community.vectorstores import Qdrant

docs = DirectoryLoader("./data", glob="**/*.pdf", loader_cls=PyPDFLoader).load()
chunks = RecursiveCharacterTextSplitter(chunk_size=700, chunk_overlap=80).split_documents(docs)

Qdrant.from_documents(
    chunks,
    OpenAIEmbeddings(model="text-embedding-3-small"),
    url="http://localhost:6333",
    collection_name="kb",
)
print(f"Ingested {len(chunks)} chunks")

# rag.py
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_community.vectorstores import Qdrant
from qdrant_client import QdrantClient

vs = Qdrant(
    client=QdrantClient(url="http://localhost:6333"),
    collection_name="kb",
    embeddings=OpenAIEmbeddings(model="text-embedding-3-small"),
)
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

def rag_answer(question: str) -> dict:
    docs = vs.similarity_search(question, k=4)
    context = "\n\n".join(f"[{i+1}] {d.page_content}" for i, d in enumerate(docs))
    prompt = (
        "Answer ONLY using the context. If unknown, say you don't know.\n\n"
        f"Context:\n{context}\n\nQuestion: {question}"
    )
    return {
        "answer": llm.invoke(prompt).content,
        "sources": [d.metadata.get("source") for d in docs],
    }

Architecture

PDFs ─► Loader ─► Splitter ─► Embeddings ─► [Qdrant] │ User Q ─► Embed ─► Qdrant top-k ─► Prompt + Ctx ─► LLM ─► Answer + Sources

Common mistakes avoid

  • Chunks too big = poor recall. Too small = no context.
  • Forgetting temperature=0 for factual Q&A.
  • Not returning sources — clients demand it.
  • Re-ingesting on every server restart. Ingestion is a separate script.
Advanced tip optional: add hybrid search (BM25 + vector) and a reranker (Cohere Rerank or bge-reranker). Big quality bump.

Day 3 — Memory, Streaming, Sessions, Rate Limits

Learning objectives

  • Make the bot feel like a real product: streaming, per-user history, abuse protection.

Concepts

  • Conversation memory: store messages per session_id in Postgres/Redis.
  • Streaming (SSE): tokens flow as generated → 5× faster feel.
  • Rate limiting: per-API-key + per-IP, protects cost.
  • Tracing: LangSmith / Langfuse to see every prompt & response.

Tools / libraries

sqlalchemy + SQLite (start) → Postgres later, redis, slowapi, sse-starlette, langfuse

Mini project: stateful streaming chat

from sse_starlette.sse import EventSourceResponse

@app.post("/chat/stream")
async def chat_stream(body: ChatIn, x_api_key: str = Header(...)):
    history = load_history(body.session_id)
    async def gen():
        full = ""
        async for chunk in llm.astream([*history, ("user", body.message)]):
            full += chunk.content
            yield {"data": chunk.content}
        save_message(body.session_id, "user", body.message)
        save_message(body.session_id, "assistant", full)
    return EventSourceResponse(gen())

Common mistakes avoid

  • Storing entire history forever → token costs explode. Cap at last 10–20 turns or summarize older ones.
  • No request IDs in logs → debugging is impossible. Add a UUID per request.
Advanced tip optional: moderation step (OpenAI moderation endpoint) before LLM call protects you from liability.

Day 4 — Deployment: Localhost → Public URL

Learning objectives

  • Containerize, deploy, get a public HTTPS URL you can send to a client.

Concepts

  • Docker: same behavior everywhere; image = frozen app + deps.
  • PaaS vs IaaS: Render / Railway / Fly.io handle TLS, scaling, env vars. AWS is overkill for week 1.
  • Managed vector DB: move to Qdrant Cloud / Pinecone — local Docker dies with your laptop.
  • Secrets: env vars in dashboard, never in code.

Dockerfile

FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
ENV PORT=8000
CMD ["sh", "-c", "uvicorn app:app --host 0.0.0.0 --port $PORT"]
  1. Push repo to GitHub.
  2. Render → New Web Service → connect repo → set env vars → deploy.
  3. Re-run ingestion pointing at Qdrant Cloud URL.
  4. Test the public URL with curl and /docs.

Architecture

[Client] ─► https://yourbot.onrender.com ─► FastAPI container ├─► Qdrant Cloud ├─► OpenAI └─► Postgres (Render add-on)

Common mistakes avoid

  • Binding to 127.0.0.1 in container → unreachable. Use 0.0.0.0.
  • Letting pip install run at runtime — bake into the image.
  • SQLite inside container — wipes on redeploy. Use the managed Postgres add-on.
Advanced tip optional: GitHub Action that runs tests + docker build on every push, with auto-deploy on main.

Learning objectives

Concepts

  • CORS: browsers block cross-origin by default. Enable CORSMiddleware for your widget domain.

  • Signature verification: always verify webhook signatures.

Day 6 — Productize: Multi-Tenant, Configurable Template

Learning objectives

  • Turn "my bot" into "a bot any business can buy in 30 minutes."

Concepts

  • Multi-tenancy: one deployment, many clients, data isolated per tenant_id.
  • Config over code: new client = new DB row, not new repo.
  • Vector isolation: per-tenant collection or metadata filter.

Data model

tenants(id, name, api_key, system_prompt, brand_color, allowed_origins)
documents(id, tenant_id, filename, status)
chunks → vector DB with metadata.tenant_id
sessions(id, tenant_id, user_ref, created_at)
messages(id, session_id, role, content, created_at)

Tenant-scoped retrieval

docs = vs.similarity_search(
    question, k=4,
    filter={"must":[{"key":"tenant_id","match":{"value":tenant.id}}]},
)

Onboarding flow (the thing you sell)

  1. Client signs up → create tenant row + API key.
  2. Admin uploads docs via POST /admin/upload.
  3. Background job ingests + embeds with tenant_id metadata.
  4. Client pastes widget script with their key.
  5. Live in < 1 hour.

  • Building a billing system in week 1. Use Stripe Payment Links + manual invoicing until 5+ customers.

Datasets you can ingest today for credible demos

  • SEC EDGAR 10-K / 10-Q filings — free, real, finance-relevant.
  • Hugging Face Datasets — search by domain (medical, legal, customer-support).
  • MS MARCO, HotpotQA, FiQA — for RAG quality eval.
  • Public docs sites — Stripe, Twilio, Supabase, Kubernetes, AWS, Azure. Scrape with crawl4ai or firecrawl.
  • Wikipedia dumps — for generalist demos.
  • Kaggle — vertical-specific corpora (reviews, support tickets, medical Q&A).

Evaluation & observability tooling

  • Langfuse — open-source LLM observability, free cloud tier.

  • promptfoo/promptfoo — regression-test prompts in CI.
  • Arize Phoenix — local tracing & eval.

Non-Negotiables (read every morning)

  1. Ship daily. A broken thing online > a perfect thing on localhost.
  2. One stack. No tool swaps mid-week.
  3. Sources in every RAG answer. Trust = revenue.
  4. Tenant filter on every vector query. Test it.
  5. Demo > deck. Build the demo before the slides.
  6. Sell before you scale. First client teaches you what to build next.

Start Now — Day 1 Kickoff

  1. mkdir ai-agency-bot && cd ai-agency-bot
  2. python -m venv .venv ; .venv\Scripts\activate
  3. pip install fastapi uvicorn openai python-dotenv pydantic
  4. Create .env with OPENAI_API_KEY=... and APP_API_KEY=dev-secret-123
  5. Paste the Day 1 app.py, run uvicorn app:app --reload, hit http://localhost:8000/docs.
